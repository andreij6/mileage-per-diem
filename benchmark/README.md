# Performance: a startup budget the build enforces

> **TL;DR:** The median cold start is **272 ms** to first frame with the Baseline Profile. Macrobenchmark measures it, and Gradle fails the build if it goes over 600 ms. The release APK is **3.0 MB**.

| Cold start · API 36 emulator · median of 10 | First frame (TTID) | Fully drawn (TTFD) |
|---|---|---|
| With Baseline Profile + startup profile | **272 ms** | **395 ms** |
| No compilation | 287 ms | 434 ms |

```bash
./gradlew :app:generateBaselineProfile                                               # record profiles on a device
./gradlew :benchmark:connectedBenchmarkReleaseAndroidTest :benchmark:verifyStartupBudget  # measure, then fail if > 600 ms
```
`verifyStartupBudget` reads Macrobenchmark's JSON output and fails if the median TTID is over `-PstartupBudgetMs` (default 600), so a slow startup can't merge unnoticed.

## What keeps startup fast
- **Nothing heavy in `Application.onCreate`.** WorkManager's auto-initializer is removed, so it starts on first use. Analytics, the demo seeder and the tracking and widget initializers are `dagger.Lazy`, and the initializers run *after* the first frame.
- **Analytics never blocks.** `track()` only enqueues; JSON encoding and Room writes happen in batches on IO.
- **Room opens lazily** on the first query, off the main thread. The 168 KB per diem database is only copied out of the APK the first time per diem data is needed.
- **Baseline and startup profiles** (22,884 rules) with dex layout optimization. They are generated by a real journey: seed data → Home → trip detail.
- **TTFD is honest.** Home calls `ReportDrawnWhen { !loading }`, so "fully drawn" means the trip list and month total are on screen.

## What keeps the APK small (3.0 MB)
R8 full mode with `-repackageclasses`, resource shrinking, English-only resources, subset variable fonts (−768 KB), vector icons instead of an icon library, no map SDK, no AppCompat, and no JSON library (analytics uses a 60-line flat JSON codec).
